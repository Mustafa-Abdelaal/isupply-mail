# Email fixture corpus (conformance suite)

Byte-exact `.eml` messages plus [`manifest.json`](manifest.json), the **answer key** describing how a
correct client interprets each one. It's stack-independent: the repo's reference parser
(`scripts/email/emaillib.py`) passes it today, and the app's MIME layer must pass the same suite once
the stack is chosen.

## What's covered

| # | Fixture | Edge case |
|---|---|---|
| 001 | plain-text | baseline US-ASCII text/plain |
| 002 | multipart-alternative-qp | plain+HTML, quoted-printable, mixed encoded-word subject |
| 003 | arabic-rfc2047 | Arabic names and subject across several encoded-words, bidi body |
| 004 | windows-1256-legacy-charset | legacy Arabic charset (Q-encoded subject, QP body) |
| 005 | inline-image-cid | multipart/related with a cid: image (inline, not an attachment) |
| 006 | attachments-rfc2231 | RFC 2231 filenames incl. continuations, RFC 2047 in parameters |
| 007 | outlook-nested-structure | mixed(related(alternative), image) + docx (Outlook shape) |

| 011 | html-xss-payloads | **security**: every common active-content vector + phishing link |

| 013 | calendar-invite | iTIP REQUEST with TZID and folded lines |

## Using the corpus in tests

Iterate over `manifest.json → fixtures[]`, parse each `file`, and assert every key in `expect`. The
semantics of each key are documented in `manifest.json → expect_keys`, and implemented executably in
`scripts/tests/_support.py::conformance_errors`. Mirror that function in the app's test suite.
`threads[]` lists messages that must group into one conversation.

## Adding fixtures

Use `/email-fixture`. Synthetic fixtures are generated by `generate_synthetic.py` (deterministic, and
CI runs `--check`). Real-world messages are accepted only after `scripts/email/anonymize_eml.py` and a
manual review, with `"origin": "anonymized"`. Never hand-edit or reformat `.eml` files, which are CRLF
and byte-exact (`.gitattributes`: `*.eml -text`).

## Seeding the dev mail server

`scripts/dev-mail seed` APPENDs every fixture into the folder and flags given by its `seed` entry
(INBOX, Archive, Reports, Junk), so the app shows realistic data during development.
